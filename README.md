# بيت لاهيا تك — موقع التسجيل

صفحة هبوط + نموذج تسجيل لكميونتي تقني بيت لاهيا. التسجيلات بتنحفظ في **Cloud Firestore**، والموقع بينرفع على **Firebase Hosting**.

## الملفات

```
public/
  index.html          صفحة الهبوط (/) — الأهداف، الفئات، المجالات، الأسئلة (عربي RTL، الهوية البصرية: ليل/زمرّد/فراولة)
  join.html           صفحة التسجيل (/join) — الفورم
  admin.html          لوحة الإدارة (/admin) — admin.js + admin.css
  styles.css          التصميم المشترك
  site.js             اللاندج بيج: تحميل المحتوى والفعاليات من Firestore + الأنيميشن
  app.js              منطق الفورم: التحقق + الإرسال + احترام إغلاق التسجيل
  firebase-init.js    تهيئة Firebase المشتركة (Firestore / Auth، والمحاكي على localhost)
  content-defaults.js النصوص الافتراضية للاندج بيج والإعدادات
  motivation.js       الـ50 جملة تحفيزية (جملة لكل بكسل بالفراولة) — عدّلها من هون
  firebase-config.js  اتركه null على Firebase Hosting (الإعدادات بتنقرأ تلقائياً)
  favicon.svg, 404.html
firebase.json         إعدادات الاستضافة + headers أمان + الكاش + المحاكيات
firestore.rules       قواعد الحماية: الموقع بيقدر "يضيف" تسجيل صالح بس، ما بيقدر يقرأ أو يعدّل أو يحذف
.firebaserc           اسم المشروع (غيّره لمشروعك)
```

## النشر الحالي

- الموقع: https://beitlahia.tech (التسجيل: `/join`). الدومين من Cloudflare، وسجلاته على **DNS only** (الغيمة الرمادية)، والعنوان القديم `beit-lahia-tech.web.app` لسا شغال
- `www.beitlahia.tech` بيحوّل على `beitlahia.tech` (من إعدادات الدومين بـ Firebase Hosting)
- المشروع: `flutter-app-distribution-a4166` — موقع استضافة منفصل `beit-lahia-tech` جوّا المشروع
- قاعدة البيانات: Firestore `(default)` بموقع `nam5`
- التسجيلات: [Firestore › members](https://console.firebase.google.com/project/flutter-app-distribution-a4166/firestore/data/~2Fmembers)

لتحديث الموقع بعد أي تعديل:

```bash
firebase deploy --only firestore:rules,hosting
```

> ملاحظة: القواعد بتقفل أي collection مش مذكورة فيها (`members`، `site`، `events`، `gallery`، `galleryFull`، `team`، `stats`، `admins`، `workshops`، `workshopRegs`، `certificates`). إذا تطبيق الفلاتر بنفس المشروع احتاج Firestore لاحقاً، لازم تضيف قواعده لنفس ملف `firestore.rules`.

## لوحة الإدارة (`/admin`)

التبويبات:
- **التسجيلات:** جدول + إحصائيات + بحث وفلترة (منها حسب المنطقة) + تعليم «تواصلنا» + تصدير Excel (CSV). الحذف بيودّي التسجيل لـ **سلة المحذوفات**، ومنها بتقدر ترجّعه، وبينحذف نهائياً لحاله بعد 30 يوم.
- **الزيارات:** كم واحد فتح الصفحة الرئيسية، وصفحة التسجيل، وبلّش يعبّي الفورم، وسجّل (آخر 7 أو 30 يوم)، ورسم للزيارات باليوم. العدّاد (`track.js` → `stats/{YYYY-MM-DD}`) بيعدّ كل متصفح مرة باليوم لكل صفحة، بدون بيانات شخصية وبدون كوكيز، وما بيعدّ متصفح الأدمن.
- **محتوى الصفحة:** تعديل كل نصوص اللاندج بيج (الواجهة، من نحن، الأهداف، رحلة العضو، المجالات، الدعوة، الأسئلة). بيظهر على الموقع فوراً.
- **الفعاليات:** إضافة فعالية/دورة/إعلان، نشر أو إخفاء، تعديل، حذف. سكشن الفعاليات بيظهر على الصفحة بس لما يكون في شي منشور.
- **المعرض:** رفع صور (بتتصغّر تلقائياً بالمتصفح وبتنحفظ بـ Firestore، بدون Cloud Storage أو خطة مدفوعة)، وصف، نشر/إخفاء، ترتيب، حذف. سكشن «معرض الصور» مخفي من الصفحة الرئيسية لحد ما تنشر أول صورة.
- **الأعضاء:** سكشن «أعضاء المجتمع» بالصفحة الرئيسية، **مخفي افتراضياً** وبيتفعّل بزر بأول التبويب (`site/settings.showMembers`). الأعضاء بتضيفهم بإيدك (`team`): صورة (بتنقص لمربع)، اسم، دور، نبذة، رابط، ونشر/إخفاء وترتيب. السكشن ما بيبيّن إلا لما يكون مفعّل وفي عضو منشور واحد على الأقل. هدول مش التسجيلات.
- **التواصل:** رقم واتساب الإدارة، وإيميل التواصل، وخانة لكل منصة سوشيال (فيسبوك، إنستغرام، لينكدإن، X، تيليغرام، يوتيوب، تيك توك، GitHub، قناة واتساب) وخانتين «رابط آخر». كل خانة بتتأكد إنه الرابط من منصتها، وفي معاينة حيّة لشكل الأيقونات بالفوتر. الخانة الفاضية ما بتطلع. إذا ما انحفظ ولا مرة، بيطلع الرقم وصفحة الفيسبوك الافتراضيين من `content-defaults.js`.
- **الإعدادات:** رابط قروب الواتساب (بيطلع بعد التسجيل)، وزر **نسخة احتياطية** بينزّل كل البيانات بملف JSON. السطر فوق العنوان بالصفحة الرئيسية بيتحول لـ «التسجيل مسكّر حالياً» لحاله لما تسكّر التسجيل.
- **الإعدادات:** فتح وإغلاق التسجيل + رسالة الإغلاق (القواعد كمان بترفض التسجيل وهو مسكّر).

### إضافة أدمن (مرة وحدة لكل أدمن)

1. Firebase Console › **Authentication** › Get started › Sign-in method › فعّل **Email/Password**.
2. Authentication › Users › **Add user**: إيميل وكلمة سر الأدمن.
3. انسخ **User UID** تبعه.
4. Firestore › Start collection: اسمها `admins`، و Document ID = الـ UID، وضيف حقل مثلاً `role` = `admin`.
5. ادخل على `/admin` بالإيميل وكلمة السر.

لو دخلت بحساب مش مضاف، الصفحة بتعرضلك الـ UID تبعه عشان تنسخه للخطوة 4.

نسيت كلمة السر؟ اكتب الإيميل بصفحة الدخول واضغط «نسيت كلمة السر؟»، وبيوصلك رابط من Firebase.

### المشرفين والصلاحيات (قسم «المشرفين»)

صاحب المنصة (`habojarad305@gmail.com`) عنده كل شي، وبيظهرله قسم **«المشرفين»** بس هو. من هناك:

- **ضيف مشرف**: الاسم والإيميل والصلاحيات. بينعمل حساب للإيميل، وبيوصله إيميل «تغيير كلمة السر» يحط فيه كلمة سر بنفسه. إذا الإيميل إله حساب من قبل (مثلاً من تطبيق الفلاتر اللي على نفس المشروع)، بتنعمل **دعوة**: أول ما يسجّل دخول على `/admin` بيوصله إيميل تأكيد، وبعد ما يأكّد بتتفعّل صلاحياته.
- **عدّل الصلاحيات** لأي حد واحفظ، أو **شيل الصلاحية** (حسابه بيضل بس ما بيقدر يفوت على اللوحة)، أو ابعتله رابط كلمة سر جديد.

| الصلاحية | الأقسام |
|---|---|
| التسجيلات | التسجيلات (والإجمالي العام إذا معه كمان الورشات) |
| أعضاء المجتمع | الأعضاء |
| الفورمات والاستبيان والمدربين | المدربين، استبيان المواضيع، إعدادات الفورمات |
| الورشات والشهادات | الورشات، الشهادات |
| محتوى الموقع… | محتوى الصفحة، الفعاليات، المعرض، التواصل |
| استوديو السوشيال والنشر | استوديو السوشيال (وخدمة النشر ما بتقبل غيره) |
| الزيارات | الزيارات |
| الإعدادات | الإعدادات (النسخة الاحتياطية الكاملة بس لصاحب المنصة واللي معهم كل الصلاحيات) |

الصلاحيات مش بس إخفاء أزرار: **قواعد Firestore** بتمنع كل مشرف من قراءة أو تعديل أي بيانات برا صلاحياته (حتى من الـ console)، وكل صلاحية بتعدّل حقولها بس من `site/settings`. الأدمن اللي انضافوا من الكونسول قبل الصلاحيات (بدون `perms`) معهم كل شي لحد ما تحدّدلهم صلاحيات. المشرف المحدود بيفتح على أول قسم إله بدل «الرئيسية».

البيانات: `admins/{uid}` = `{ email, name, perms[], addedBy, createdAt }`، والدعوات بـ `adminInvites/{email}`. **لازم تنزيل القواعد** قبل ما هالشي يشتغل على الموقع الحقيقي:
```

```
اختبار القواعد على المحاكي: `firebase emulators:exec --only firestore --project demo-bitlahia "node scripts/test-rules.mjs"`. وحسابات تجريبية بصلاحيات مختلفة على المحاكي: `node scripts/seed-emulator-roles.mjs`.

## الحماية من التسجيلات الوهمية (App Check)

الكود جاهز ومطفي. شغّله لما تبدأ تنشر الرابط على نطاق واسع، أو أول ما تشوف تسجيلات وهمية:

1. اعمل مفتاح **reCAPTCHA v3** من https://www.google.com/recaptcha/admin، وحط الدومين `beit-lahia-tech.web.app`.
2. Firebase Console › **App Check** › Apps › اختار تطبيق الويب «Beit Lahia Tech» › reCAPTCHA v3 › الصق الـ **secret key**.
3. حط الـ **site key** بـ `public/firebase-config.js` بـ `appCheckSiteKey`، وارفع الموقع.
4. استنى يوم أو يومين، وشوف بـ App Check › APIs › Cloud Firestore إنه أغلب الطلبات «Verified».
5. بعدها اضغط **Enforce** على Cloud Firestore.

ملاحظة: reCAPTCHA بيزيد تحميل حوالي 150KB على كل صفحة، عشان هيك مطفي لحد ما تحتاجه.

## الورشات والشهادات

- **`workshops/{id}`**: كل ورشة doc لحالها: المعلومات (العناوين، التاريخ، المكان، الساعات، المحاور، قروب الواتساب، فتح/سكّر التسجيل) + قالب الشهادة (`cert`) + الحالة `status`: `draft` (مسودة، للأدمن بس) / `live` (منشورة) / `done` (انتهت).
- **`site/settings.currentWorkshop`**: رقم الورشة اللي بتطلع على `/workshop`. بيتغيّر لحاله لما تحفظ ورشة «منشورة».
- **نشر مجدول (`publishAt`)**: ورشة «منشورة» إلها «موعد نشر» بتضل مخفية، والقواعد بترفض قراءتها والتسجيل فيها لحد هاد الوقت. رقمها بينحفظ بـ `site/settings.nextWorkshop`، وصفحة `/workshop` بتجرّبها أول، فبالموعد بتطلع لحالها بدون ما حدا يدخل اللوحة. أول ما تفتح اللوحة بعد الموعد، بتصير هي `currentWorkshop`.
- **`/workshop`**: صفحة الورشة الحالية ونموذج التسجيل (`workshop.html/js/css`). **`/workshop?w=<id>`** بيفتح ورشة محددة؛ إذا كانت «انتهت» بتطلع «الورشة انتهت» بدل الفورم، وإذا مسودة أو مش موجودة «الورشة مش موجودة». تحت في سكشن **«ورشاتنا السابقة»** (كل الورشات اللي حالتها «انتهت»).
- **`workshopRegs`**: التسجيلات، وكل تسجيل فيه `workshopId`. القواعد بتقبل التسجيل بس لورشة `live` وتسجيلها مفتوح.
- **`certificates/{id}`**: الشهادات الصادرة `{ name, no, date, regId?, workshopId }`. الترقيم بيكمل من «بداية رقم الشهادة» على كل الشهادات (من كل الورشات)، فما بيتكرر رقم.
- **`/certificate?id=…`**: شهادة شخص، مرسومة بقالب **ورشتها** (`workshops/{workshopId}`)، فلما تعدّل قالب ورشة جديدة الشهادات القديمة بتضل زي ما هي. شهادة قديمة ما إلها `workshopId` بتاخد الورشة الحالية. بدون `id` بتطلع نسخة فارغة للطباعة (`?w=<id>` لورشة محددة).
- الشهادة بترسمها `workshop-shared.js` + `certificate.css`، نفس الكود للصفحة ولمعاينة لوحة الإدارة.

### بلوحة الإدارة

- تبويب **«الورشات»**: فوقه **«سجل الورشات»** (كل ورشة: العنوان، التاريخ، الحالة، عدد المسجّلين والحاضرين والشهادات، «إدارة»، «نسخ الرابط»، حذف). كل إشي تحته (المعلومات، المحاور، التسجيلات، الحضور، إصدار الشهادات، التصدير) وتبويب **«الشهادة»** بيشتغلوا على الورشة المختارة.
- **«+ ورشة جديدة»** بينسخ محتوى الورشة المختارة (النصوص، المحاور، قالب الشهادة) وبيفضّي التاريخ والوقت والمكان ورابط القروب، وبتبدأ «مسودة». عدّلها، وبس تجهز خلّي حالتها «منشورة» واحفظ: بتصير هي اللي على `/workshop`. القديمة خلّي حالتها «انتهت».
- الحذف بس لورشة ما إلها تسجيلات ولا شهادات، ومش الظاهرة على الموقع. ما بتنصدر شهادات لورشة «مسودة».
- أول مرة بتفتح اللوحة بعد التحديث، إذا ما في ورشات بتنعمل أول ورشة من النص الافتراضي (**مسودة**)، وكل تسجيل أو شهادة قديمة بتنربط فيها لحالها.
- **موعد النشر** بمعلومات الورشة (بيشتغل بس لما الحالة «منشورة»): فاضي = بتطلع فوراً لما تحفظ، أو حط تاريخ وساعة وبتطلع ويفتح التسجيل لحاله بهاد الوقت. بسجل الورشات بتبيّن شارة «مجدولة» مع الموعد.

## استوديو السوشيال (لوحة الإدارة › «استوديو السوشيال»)

القوالب الثمانية المعتمدة (منشور تعريفي، خدماتنا، نبحث عن مواهب، اقتباس، حدث/ورشة، ستوري، شكراً لكم، تابعونا) صاروا جوا لوحة الإدارة: بتختار القالب، بتعدّل نصوصه (والصورة بالقوالب اللي فيها صورة)، بتشوف معاينة حيّة، وبعدين:

- **«نزّل PNG»**: بيشتغل دايماً، حتى قبل ما تربط أي حساب.
- **«انشر الآن» / «جدول المنشور»**: بينشر على صفحة الفيسبوك وحساب الإنستغرام، هلّق أو بموعد (لحد 75 يوم لقدّام). قالب «ستوري» بينزل على إنستغرام كستوري.
- **قائمة «المنشورات»**: كل منشور وحالته (مجدول، انتشر، انتشر جزئياً، فشل) مع رابطه. المجدول بتقدر تلغيه أو تنشره فوراً، واللي فشل بتعيد تجربته (بيعيد بس المنصة اللي فشلت).

### محرر التصميم

كل قالب مبني من **عناصر** (نص، صورة، مستطيل/كرت، زر، الفراولة، الشعار، أيقونة، بكسل آرت، مربعات بكسل، خط مموّج، أيقونات السوشيال)، وكلها بتتعدّل:

- **«المحتوى»**: كل نصوص القالب بمكان واحد، للتعديل السريع.
- **«التصميم»**: اضغط على أي عنصر بالمعاينة (أو من «الطبقات») وبيطلع تحته كل خصائصه: النص، الحجم، اللون (مع ألوان الهوية جاهزة)، السماكة، الخط (Cairo أو Montserrat)، المحاذاة، الشفافية، الدوران، الصورة… وبتقدر:
  - **تسحب** العنصر لتحرّكه (بيلقط على نص اللوحة لحاله، وShift بيحرّكه بخط مستقيم)، وتسحب **المربع الأخضر** بالزاوية لتكبّره أو تصغّره، والأسهم بتحرّك بدقة (Shift = أسرع).
  - **تضيف** عنصر جديد، **تنسخه** (Ctrl+D)، **تحذفه** (Delete)، تقدّمه أو ترجّعه بين الطبقات، أو **تخفيه**.
  - تغيّر **لون الخلفية** والشبكة و**المقاس** (منشور 4:5، مربع، ستوري).
  - **تتراجع / تعيد** (Ctrl+Z / Ctrl+Y).
- **«احفظ كقالب جديد»** بيحفظ التصميم بقسم **«قوالبي»** (لكل الأدمن، بأي جهاز). لما تفتح قالب من «قوالبي» بتقدر «احفظ التعديلات» أو «احذف القالب». القوالب الأصلية ما بتتغيّر، و«رجّع الأصل» بيرجّع القالب زي ما كان.
- الشغل الحالي بينحفظ بالمتصفح لحاله، فلو سكّرت الصفحة بترجع تلاقيه.

القوالب المحفوظة بـ Firestore بمجموعة `socialTemplates` (الأدمن بس بيقرأ ويكتب). **لازم تنزيل القواعد** قبل ما «احفظ كقالب» يشتغل على الموقع الحقيقي:
```
firebase deploy --only firestore:rules --project flutter-app-distribution-a4166
```

| الملف | شو فيه |
|---|---|
| `public/social-templates.js` | القوالب كبيانات (عناصر)، ورسمها SVG، والفراولة والبكسل آرت |
| `public/admin-social.js` | الاستوديو بلوحة الإدارة: محرر التصميم، المعاينة، حفظ القوالب، التنزيل والنشر |
| `social-worker/` | خدمة النشر على Cloudflare (بتحفظ التوكن، بتنشر، وبتشغّل الجدولة كل 5 دقايق) |

النشر والجدولة بيمرّوا على **خدمة صغيرة على Cloudflare Workers** (مجانية، على نفس حساب Cloudflare اللي عليه الدومين)، لأنه توكن صفحة الفيسبوك لازم يضل سرّي، وإنستغرام بيطلب رابط عام للصورة، والجدولة بدها شي شغّال دايماً. الخدمة ما بتقبل غير أدمن مسجّل دخول (نفس شرط `admins/{uid}`).

### 1) تركيب الخدمة (مرة وحدة، أمر واحد)

```
cd social-worker
npm run setup
```
بيفتحلك المتصفح تسجّل دخول على Cloudflare (نفس الحساب اللي عليه `beitlahia.tech`)، وبعدين لحاله: بيعمل مكان التخزين (KV) وبيكتب رقمه بـ `wrangler.toml`، بيرفع الخدمة على `https://social.beitlahia.tech` (وCloudflare بيعمل الـ DNS)، وبيستنى لحد ما ترد. لما يخلص، الاستوديو بلوحة الإدارة بيكتب «خدمة النشر شغّالة».

### 2) ربط فيسبوك وإنستغرام (من لوحة الإدارة)

بالاستوديو بتطلعلك بطاقة **«ربط فيسبوك وإنستغرام»** (لصاحب المنصة بس) وفيها الخطوات مع الروابط. باختصار:

1. حساب الإنستغرام **Business أو Creator** ومربوط بصفحة الفيسبوك.
2. [developers.facebook.com/apps](https://developers.facebook.com/apps/) › Create App (حالة استخدام إدارة الصفحة، أو نوع Business). من App settings › Basic انسخ **App ID** و**App Secret**.
3. [Graph API Explorer](https://developers.facebook.com/tools/explorer/): اختار تطبيقك، User Token، وضيف الصلاحيات (البطاقة فيها زر نسخ):
   `pages_show_list, pages_read_engagement, pages_manage_posts, instagram_basic, instagram_content_publish, business_management`
   › Generate Access Token › وافق واختار الصفحة وحساب الإنستغرام.
4. بالبطاقة: الصق App ID وApp Secret والتوكن › **«جيب صفحاتي»** › اختار صفحة المجتمع › **«اربط هالصفحة»**.

الخدمة بتحوّل التوكن لتوكن طويل، وبتاخد منه **توكن الصفحة (ما بينتهي)** وحساب الإنستغرام المربوط، وبتحفظهم عندها (KV). التوكن ما بيرجع للمتصفح أبداً. بعدها بالبطاقة: «اختبار الاتصال»، «ربط من جديد / صفحة ثانية»، و«فصل الحسابات»، وبتنبّهك إذا في صلاحية ناقصة أو الصفحة ما إلها إنستغرام.

التطبيق بيضل بوضع **Development**؛ هاد بيكفي طالما اللي ربط الحساب أدمن على التطبيق وعلى الصفحة. إصدار الـ Graph API بـ `GRAPH_VERSION` بـ `wrangler.toml`؛ ميتا بتوقّف كل إصدار بعد سنتين تقريباً، فحدّثه (وارفع بـ `npx wrangler deploy`) لما يقرب يخلص.

### تجربة الاستوديو محلياً (بدون حسابات)

```
node social-worker/test/dev-server.mjs
```
وبتيرمنال تاني شغّل الموقع (`python -m http.server 5055 -d public`) وافتح `http://localhost:5055/_studio.html`. هاي نسخة الاستوديو مع خدمة نشر وهمية وتخزين قوالب وهمي (بالمتصفح): كل شي بيشتغل (التصميم، حفظ القوالب، النشر، الجدولة، الإلغاء) بدون ما ينشر أو يحفظ إشي حقيقي. صفحات `_*.html` ما بتنرفع مع الموقع.

اختبارات الخدمة: `cd social-worker && npm test` (النشر والجدولة، وربط الحسابات من اللوحة). وبخدمة النشر الوهمية (`dev-server.mjs`) بتقدر تجرّب بطاقة الربط كمان: أي App ID أرقام، والـ App Secret = 32 حرف `a`، وأي توكن.

### ملاحظات

- إنستغرام بيقبل JPEG بس، فالنشر بيبعت JPEG، والتنزيل PNG.
